# Spec: SM Import pipeline + SM Schedule
Sheets covered: **SM Import**, **SM Audit Trail**, **QP SM Audit Trail**, **Pivot**, **SM Schedule**.
VBA covered: `ImportTSI`, `ImportQPSM`, `ImportQPPipe`, `Clear_Existing_Takeoff`, `Yes_No_Import_New_Job`, `AutoFillCells`, plus helpers `Misc_Commands.SetImportRanges/NextOpenCell/ClearExtra`.
Static data: `sm-import-schedule.data.json` (generated by `gen_sm_import_schedule_data.py`).

---

## 1. Purpose in the bid workflow

External takeoff software (TSI/"MAP" and QuotePro/"QP" — both produce `FESTR*.txt` tab/comma-delimited exports) measures the sheet-metal job. VBA macros load those text files into raw **audit trail** sheets, pivot them by Floor/Service/Type/Material/CutType on the **Pivot** sheet, and paste the aggregated rows into **SM Import**. TakeOff's **CAE group** (rows 10–34) then buckets SM Import lines into ~24 standard categories via SUMPRODUCT (mapping table already documented in `takeoff.md` §CAE / `takeoff.data.json.caeMappingTable`). So this whole group is a **data-ingestion funnel: text export → audit trail → pivot → SM Import → TakeOff CAE**.

**SM Schedule** is unrelated to the import funnel: it is a printable 48-week Gantt/labor-planning chart keyed to the job's work packages (TakeOff group names via Breakdown). **Nothing reads SM Schedule** — it is output-only. In particular, `Info_Schedule_Start_Date`/`Info_Schedule_End_Date` are **NOT** fed by SM Schedule; they are locked literal dates on `'Crew Mix'!I5/I7` (the SM labor-rate period, see crew-mix.md quirk 7).

### What the HTML app needs (recommendation)
- Replace the three VBA imports with a **paste/upload import zone** (accepts tab- or comma-delimited text with quoted fields, i.e. the raw FESTR export or a spreadsheet paste). Two parsers: TSI schema (30 cols) and QP schema (15 cols) — see data.json `tsiAuditTrail.columns` / `qpAuditTrail.columns`. Keep the raw rows (audit trail) for traceability, then run the group-by + mapping described in §5.3/§5.4 in JS. Also allow **direct row entry/edit in SM Import** as an app improvement (in Excel the imported A:K cells are written by macro under `userinterfaceonly` protection; only L/N are user-editable — but direct entry is the natural replacement for the file-based import).
- Implement SM Schedule as a simple task-list + computed Gantt (§6); it's self-contained and cheap.
- Skip `ImportQPPipe` (dead code: its target sheets `QP Pipe Audit Trail` / `Pipe Import` do not exist in this workbook — see §8 quirks).

## 2. SM Import — layout & behavior

Protected sheet, saved state is EMPTY (the sample job's CAE was already "relocated"). max_row 14, cols A–O.

| Range | What |
|---|---|
| Row 7 | Grand totals: `F7 =SUM(SMImport_Qty)`, `H7 =SUM(SMImport_CalcFieldHours)` (**named `CAE_Field_Hours_Total`**), `J7 =SUM(SMImport_CalcShopHours)` (**`CAE_Shop_Hours_Total`**), `K7 =SUM(SMImport_MaterialCost)` (**`CAE_Material_Cost_Total`**) |
| Row 8 | Headers: A Floor, B Service, C Type, D Material, E Cut Type, F Qty, G Field Hours, H Calculated Field Hours, I Shop Hours, J Calculated Shop Hours, K Material Cost, L Field % of Labor, M Field Difficulty, N Shop % of Labor, O Shop Difficulty |
| Rows 9+ | One line per pivot aggregate (Floor×Service×Type×Material×CutType). A–G, I, K are pasted values (user-editable); H, J, M, O computed; L, N editable % formulas |

### USER INPUTS (unlocked)
- **L9..Ln "Field % of Labor"** (nf `0%`): default formula `=IF(G9="","",1)` → 100%. The estimator overrides with e.g. 1.15 to mark difficulty (overwriting the formula).
- **N9..Nn "Shop % of Labor"**: default `=IF(I9="","",1)`.
- A:G, I, K rows 9..n (Floor, Service, Type, Material, Cut Type, Qty, Field Hours, Shop Hours, Material Cost) are **macro-written values** — sheets are protected with `userinterfaceonly:=True` (password `/\rct1c`), so VBA writes them while the UI can't. In the app these become the import-zone output grid (editable, since the app replaces the macro). Only row 9's H/J/L:O formulas exist in the saved file; VBA autofills them down to the imported row count.

### CALCULATIONS (locked, per row r)
```js
H_r = G_r === '' ? '' : (L_r === 0 ? G_r : G_r * L_r)      // Calculated Field Hours
J_r = I_r === '' ? '' : (N_r === 0 ? I_r : I_r * N_r)      // Calculated Shop Hours
M_r = L_r === '' ? '' : (L_r === 0 || L_r === 1 ? 'Standard' : L_r < 1 ? 'Easy' : 'Hard')   // Field Difficulty
O_r = N_r === '' ? '' : (N_r === 0 || N_r === 1 ? 'Standard' : N_r < 1 ? 'Easy' : 'Hard')   // Shop Difficulty
F7 = sum(F rows); H7 = sum(H); J7 = sum(J); K7 = sum(K)
```

### Named ranges (dynamic!)
`SMImport_Type` C9:C78, `SMImport_Material` D9:D78, `SMImport_CutType` E9:E78, `SMImport_Qty` F9:F78, `SMImport_CalcFieldHours` H9:H78, `SMImport_CalcShopHours` J9:J78, `SMImport_MaterialCost` K9:K78 — the $78 is just the last saved extent; VBA `SetImportRanges` re-points them to `row 9 .. lastRow+2` after every import/clear. **App: treat as "all rows of the SM Import table".**

### Cross-sheet OUTPUTS
- TakeOff CAE rows 10–33: `=SUMPRODUCT((SMImport_Type="X")*(SMImport_Material="Y")*(SMImport_CutType="Z"), SMImport_Qty|CalcFieldHours|CalcShopHours|MaterialCost)` (per-row criteria in takeoff.data.json).
- TakeOff row 34 (Miscellaneous remainder): `E34='SM Import'!F7-SUM(E10:E33)`, `H34=CAE_Field_Hours_Total-SUM(H10:H33)`, `K34=CAE_Shop_Hours_Total-SUM(K10:K33)`, `M34=ABS(CAE_Material_Cost_Total-SUM(M10:M33))`.
- No other consumers.

## 2b. What the app implements (added after the port)

`readSmImportFile()` / `parseTakeoffExport()` in `src/parts/07e_ui_smimport.js` read the raw
exports directly and do the pivots' work. Format is detected from the header row, so a renamed
file still works.

**QuickPen `FESTR_QP.txt` — complete.** Every field the "QP All" pivot uses is in the export
(cache fields 0-14 are all raw columns). Group by Floor / Service Type / Shape / Material /
Cut Type; Qty and field hours from `Labor Type = Field` rows only, shop hours from `Shop` rows,
material cost from everything except blank and `N/A`, `Cut Type = Wrap` excluded, and
`3003H14Aluminum` renamed to `Alum` — exactly the macro's filters.

**TSI `FESTR.txt` — partial, deliberately.** The "All Material" pivot sums cache fields 30, 31
and 34 (*Fab Hours*, *Install Hours*, *Total Material Cost*).

**CORRECTED.** An earlier revision of this document said these were "not recoverable from the
extract" and the app therefore summed *Install time* / *Fab time* raw and left material cost
blank. That was wrong, and it made every TSI hour **60x too large**. They are not sheet columns
and they are not in the VBA — they are pivot **calculated fields**, and they survive verbatim in
`xl/pivotCache/pivotCacheDefinition2.xml`:

```xml
<cacheField name="Fab Hours"               formula="'Fab time'/60"                     databaseField="0"/>
<cacheField name="Install Hours"           formula="'Install time'/60"                 databaseField="0"/>
<cacheField name="Insul Fab Hours"         formula="'Insul Fab time'/60"               databaseField="0"/>
<cacheField name="Fab Hours No Insulation" formula="('Fab time'-'Insul Fab time') /60" databaseField="0"/>
<cacheField name="Total Material Cost"     formula="'M-Rate'-'Ext Wrap Cost'"          databaseField="0"/>
```

So, definitively:

| SM Import column | Definition |
|---|---|
| F Qty | `SUM(Qty)` |
| G Field Hours | `SUM(Install time) / 60` — **the export writes MINUTES** |
| I Shop Hours | `SUM(Fab time) / 60` — minutes too |
| K Material Cost | `SUM(M-Rate − Ext Wrap Cost)` |

Note *Fab Hours* is plain `Fab time/60`; it does **not** add *Insul Fab time* (that has its own
field, `Insul Fab Hours`, which no data field uses). `Ext Wrap Area` / `Ext Wrap Cost` are copied
to the named ranges `Ext_Insul` / `Ext_Insul_Cost` for the insulation side and are not part of the
SM Import block.

The QuickPen cache (`pivotCacheDefinition1.xml`) has **no** calculated fields — its *Labor Hours*
are already hours. Only the TSI export is in minutes.

## 4. Pivot sheet (Excel PivotTables — replace with JS group-by)

Three PivotTables, refreshed by VBA (a 4th, "QP Pipe All", is referenced by dead code only):

| Pivot | Source | Page filter | Row fields | Value fields (all SUM) |
|---|---|---|---|---|
| **All Material** (A1) | SM Audit Trail | Bought Out = (All) | Section, Service, Service Type, Material, Cut Type | Qty, Install Hours, Fab Hours, Total Material Cost, Ext Wrap Area, Ext Wrap Cost |
| **QP All** (M1) | QP SM Audit Trail | Labor Type (multi) | Floor, Service Type, Material, Shape, Cut Type | Material Cost, Labor Hours, Qty |
| **QP Wrap** (V1) | QP SM Audit Trail | Cut Type = Wrap | — | Material Cost, Area |

"Install Hours"/"Fab Hours"/"Total Material Cost" are **calculated pivot fields** of the TSI source. Their definitions are recorded in the pivot cache and are quoted in full in §2b — `'Install time'/60`, `'Fab time'/60`, `'M-Rate'-'Ext Wrap Cost'`. (An earlier revision called them unrecoverable and guessed; see the correction in §2b.) The whole Pivot sheet becomes an internal `groupBy()`; no UI needed.

Row-field **order** matters only for the order rows land in SM Import, but match it anyway so an import can be read down beside the old spreadsheet's: TSI sorts Section → Service → Service Type → Material → Cut Type; QuickPen sorts Floor → Service Type → **Material → Shape** → Cut Type (note Material before Shape, even though the macro pastes Shape into column C and Material into D).

`Ext_Insul` (Pivot!J8:J65) / `Ext_Insul_Cost` (Pivot!K8:K65) — workbook names re-created by both import macros pointing at the wrap-area/wrap-cost pivot columns. **No formula anywhere consumes them** (legacy). Safe to drop; note for fidelity.

## 5. Import macros → app logic

### 5.1 `Yes_No_Import_New_Job.YesNoMessageBox` (the "start new job" entry)
Unhides all working sheets (Breakdown stays veryHidden); if `'MCAA RECAP'!A2` ≠ "Existing" → first run: sets A2="Existing", prompts **Job Name** → `'MCAA RECAP'!H6` (= `Info_Job_Name`) sanitizing filename-hostile chars (`/ \ " | [ ] { }` → `-`, `.` → `_`), prompts **Bid Number** → `'MCAA RECAP'!B7`, clears SM Audit Trail rows 2+, refreshes pivots, saves. App equivalent: "New Bid" flow = job name + bid number fields; sanitization only matters for export filenames.

### 5.2 Common import plumbing
- `Auto_fill_cells`: after pasting a pivot row-field column, fill blank cells downward with the last non-blank value above (pivot outline → flat table). Stop at "(Blank)".
- `NextOpenCell`: QP import appends below existing TSI rows (first empty cell per column).
- `Delete_Blank`: replace literal "(blank)" with "" everywhere.
- `SetImportRanges`: re-register SMImport_* names to actual extent.
- Formats/formulas of row 9 (H, J, L:O) are autofilled down to the last imported row.

### 5.3 `Import_TSI` (TSI/MAP ductwork)
1. Clear SM Audit Trail (A:CU), load `FESTR.txt` (tab+comma delimited, `"` qualifier), paste all.
2. Global replace **"Spiral Straight" → "Decoiled Straight"** (partial match).
3. Refresh pivot **All Material**; copy pivot columns → SM Import: Section→A, Service→B, Service Type→C, Material→D, Cut Type→E (each followed by fill-down), Sum of Qty→F, Sum of Install Hours→G, Sum of Fab Hours→I, Sum of Total Material Cost→K.
4. Delete "(blank)", set names, autofill L:O/H/J + formats, enable autofilter, re-point Ext_Insul(_Cost) to wrap columns.

**App pseudo-code** (working directly on raw rows — skips the pivot layer):
```js
rows = parseDelimited(text, {delims:['\t',','], quote:'"'});          // TSI schema, data.json tsiAuditTrail.columns
rows.forEach(r => forEachCell(r, v => v.replaceAll('Spiral Straight','Decoiled Straight')));
groups = groupBy(rows, ['Section','Service','Service Type','Material','Cut Type']);
smImport = groups.map(g => ({floor:g.Section, service:g.Service, type:g['Service Type'],
  material:g.Material, cutType:g['Cut Type'], qty:sum(g,'Qty'),
  fieldHours:sum(g,'Install time')/60, shopHours:sum(g,'Fab time')/60,
  materialCost:sum(g, r => r['M-Rate'] - r['Ext Wrap Cost']), fieldPct:1, shopPct:1}));
```
The `/60` is not optional — the export writes minutes (§2b). A **pre-aggregated paste** is still accepted as a second path (user copies the SM Import block A:K straight out of the old workbook), but it is a convenience now, not a fallback for missing knowledge.

### 5.4 `Import_QP` (QuotePro sheet metal)
1. Clear QP SM Audit Trail rows 2+, load `FESTR_QP.txt` (same parsing), paste.
2. Replacements: **"3003H14Aluminum"→"Alum"**, **"Flex Connector"→"Canvas Connector"** (whole-cell).
3. Row fixups: rows where col E (Cut Type slot) = "Hanger" or "Canvas Connector" → insert-shift that value left into D (these items have no Cut Type, the export mis-aligns); Material col = 0 → "N/A".
4. Refresh QP All + QP Wrap pivots; hide Cut Type "Wrap" and Labor Type "(blank)" from QP All.
5. Copy into SM Import **appending after existing rows**: Floor→A, Service Type→B, Shape→C, Material→D, Cut Type→E (fill-down each); then with Labor Type filter =Field: Sum of Qty→F, Sum of Labor Hours→G; filter =Shop: Sum of Labor Hours→I; filter = all but "(blank)"/"N/A": Sum of Material Cost→K.
6. Same tail steps as TSI; Ext_Insul(_Cost) re-pointed to **QP Wrap** pivot (Cut Type=Wrap: Area / Material Cost; error fallback to "(Blank)" page).

**App pseudo-code:**
```js
rows = parseDelimited(text);                                   // QP schema, data.json qpAuditTrail.columns
applyReplacements(rows); fixHangerShift(rows); fixMaterialNA(rows);
base   = rows.filter(r => r['Cut Type'] !== 'Wrap' && r['Labor Type'] !== '');
groups = groupBy(base, ['Floor','Service Type','Shape','Material','Cut Type']);
appendToSmImport(groups.map(g => ({floor:g.Floor, service:g['Service Type'], type:g.Shape,
  material:g.Material, cutType:g['Cut Type'],
  qty:sum(g.filter(labor='Field'),'Qty'), fieldHours:sum(g.filter(labor='Field'),'Labor Hours'),
  shopHours:sum(g.filter(labor='Shop'),'Labor Hours'),
  materialCost:sum(g.filter(labor not in ['','N/A']),'Material Cost'), fieldPct:1, shopPct:1})));
```
Quirk to preserve: QP **Qty** sums only Field-labor rows (the macro leaves the Field filter on when copying Qty).

### 5.5 `Import_QPPipe` — DEAD in this workbook
Targets sheets `QP Pipe Audit Trail` and `Pipe Import`, neither of which exists here (macro survives from the combo SM+Pipe template; `SetImportRanges`' pipe block is commented out). Do **not** implement; mention in app docs only if a pipe variant is ever needed.

### 5.6 `Clear_Existing_Takeoff.RemoveSMImport` / `Remove_CAE_NoQuestion`
"Clear takeoff" button (confirm dialog / silent version called by Relocate CAE): clear SM Import A9:G, I9, K9 to last row+2, delete surplus rows below 15, clear both audit-trail sheets (rows 2+), refresh all pivots, re-register SMImport_* names. `RemovePipeImport` = dead (pipe sheets absent). App: "Clear SM import" action that empties the import table + stored raw rows; TakeOff CAE rows all fall to 0 automatically.

## 6. SM Schedule — 48-week Gantt

Protected; visible cols A–F, I, L–IR (G, H, J, K hidden); rows 1–212. **Standalone output** — reads `Info_Job_Name` and Breakdown!A9:A27, writes nothing.

### Layout
- **A1** `="PROJECT NAME: " & Info_Job_Name` ('MCAA RECAP'!H6). **A2** (merged A2:C2, unlocked) "PROJECT MANAGER:" — user types name into the label cell.
- **L1** label "Alternate Start Date:" / **M1** = optional user date (empty, unlocked). Cell comment: *"Any entered date becomes first date displayed in Gantt… enter a Monday for the weeks to work properly."*
- 19 package blocks of 11 rows starting row 4 (4, 15, 26, …, 202): header row + 10 task rows.
  - **A** WBS: package p, tasks p.1…p.10 (stored 4.1 for both ".1" and ".10"; ".10" via nf `0.00` — display quirk).
  - **C** package row: `=Breakdown!$A(9+i)` (→ TakeOff group names D40, D74, … see phase-codes-breakdown.md); task rows unlocked, defaults "Task A"…"Task J".
  - **D** MAN POWER — user input, purely informational (no formula consumes it).
  - **E/F** planned start/finish — task rows are date inputs; package row rolls up: `E_pkg =IF(E_first="","",MIN(E_tasks))`, `F_pkg =IF(F_first="","",MAX(F_tasks))` (nf mm/dd/yy).
  - **G** STATUS (hidden col): dropdown list `Not Started, In Progress, Completed` (validation covers G4:G522; Excel keeps the leading spaces in the last two items — trim in app).
  - **H** ACTUAL FINISH DATE (hidden), **I** NOTES — inputs.
  - **J/K** hidden helpers: `J_r =IF(E_r="","",E_r-$M$3+1)`, `K_r =IF(F_r="","",F_r-$M$3+1)`; package rows MIN/MAX of block.
  - **L** Work Days `=SUM(M_r:IR_r)` (comment: "Assumes 5 work days per calendar week").
- **Gantt matrix M:IR** (240 columns = 48 weeks × 5 workdays):
  - Row 2 day numbers: M2..Q2 = 1..5 literal; then per week `+3` across the weekend and `+1` within (R2=Q2+3=8 … IR2=334). I.e. calendar-day offsets from the anchor Monday, weekends skipped.
  - Row 3 week headers (merged 5-wide M3:Q3 … IN3:IR3): **anchor** `M3 =IF(M1="", firstMondayOfMonth(MIN(all package E rollups)), M1)` where `firstMondayOfMonth(d) = DATE(YEAR(d),MONTH(d),7) - WEEKDAY(DATE(YEAR(d),MONTH(d),7),3)`; then `R3=M3+7`, `W3=R3+7`, … (+7 each).
  - Cells rows 4–212: `=IF(AND(day#>=$J_r, day#<=$K_r),1,"")` — 1 marks a scheduled workday (conditional formatting shades it; CF not in extract).

### App pseudo-code
```js
anchor = altStart ?? firstMondayOfMonth(min(packages.map(p => min(p.tasks.start))));
dayNum = d => Math.floor((d - anchor)/86400000) + 1;          // calendar-day offset
task.calStart = dayNum(start); task.calEnd = dayNum(end);
task.workDays = countWeekdayOffsets(calStart, calEnd);         // offsets whose ((n-1)%7) < 5
// render 48 weeks × 5 days; cell on iff calStart<=day<=calEnd
```
Recommend rendering bars directly from dates instead of a 240-column grid; keep Work Days & package MIN/MAX rollups for fidelity.

### User inputs summary (SM Schedule)
Per task row (190 rows): C description, D manpower, E start, F finish, G status (dropdown), H actual finish, I notes → ~1,330 potential input cells; plus A2 (PM name) and M1 (alternate start). Company constants: none (no rates/factors on any sheet in this group).

## 8. Quirks
1. **Empty saved state**: SM Import/audit trails/pivots are all zero — the sample job already ran Relocate CAE. TakeOff CAE rows legitimately read 0 from empty ranges.
2. **SMImport_* ranges are dynamic** (VBA-managed). Hard-coding $9:$78 is wrong for >70 imported lines; app should use the full table.
3. QP **Qty only counts Field rows**; Material Cost excludes Labor Type "(blank)"/"N/A"; Wrap rows excluded from SM Import entirely (they only feed the unused Ext_Insul names).
4. QP export mis-aligns Hanger/Canvas Connector rows (Cut Type column holds the Shape) — imports shift them left; text replacements: Spiral Straight→Decoiled Straight (TSI), 3003H14Aluminum→Alum, Flex Connector→Canvas Connector (QP).
5. **The TSI export is in MINUTES.** `Install time` and `Fab time` are divided by 60 by the pivot's calculated fields (§2b). Anything that sums those columns raw is 60x out. Material cost is `M-Rate − Ext Wrap Cost`, also a calculated field.
6. `Import_QPPipe`, `RemovePipeImport`, and the commented pipe block of `SetImportRanges` are dead code (no Pipe sheets in this workbook). For the record its hard-coded path is `C:\MAP-Software\EST\Exports\FESTR_QP-Mech.txt`, and `ClearExtra` — called by `Import_QP` — has an entirely commented-out body and is a no-op.
6b. **Both exports carry a header row.** `Workbooks.OpenText` uses `StartRow:=1` and the macro copies whole columns onto a cleared sheet, so row 1 of `SM Audit Trail` in the saved workbook *is* the last real `FESTR.txt`'s first line. The pivot source names are `OFFSET(...,COUNTA(row 1))`, which structurally requires headers. The importer sniffs that header row but must not depend on it — fall back to the file's shape (TSI = 30 columns, QuickPen = 15, QuickPen column 6 is Field/Shop/N/A) rather than refusing. The `+1` in the OFFSET height is where the pivot's `(blank)` group comes from: drop the trailing blank row.
6c. **Encoding is `Origin:=437`** (DOS code page), not UTF-8, and `TrailingMinusNumbers:=True` (`123-` is negative). Both delimiters — tab *and* comma — were active in the same parse, with `"` as the text qualifier.
7. SM Schedule hides its STATUS/ACTUAL FINISH columns (G, H) and helpers (J, K); validation/hidden-col lists show phantom mirrors every 256 columns / 65,536 rows (JC4:JC522 etc.) — Excel-97 wrap artifact, ignore.
8. SM Schedule anchor must be a **Monday** (comment on M1); default anchor = first Monday of the month of the earliest start, which can precede the earliest task by up to ~4 weeks and (edge) even fall after mid-month starts' first days — keep formula as-is for fidelity.
9. `Info_Schedule_Start/End_Date` ≠ SM Schedule; they're Crew Mix labor-rate period literals (crew-mix.md).
10. SM Schedule WBS ".10" rows store the same number as ".1" (11.1 vs 11.10 differ only by number format) — if the app sorts/keys by WBS, generate strings, not floats.
11. Status dropdown items 2–3 carry leading spaces in Excel (`"Not Started, In Progress, Completed"` split on comma) — trim.
12. `Yes_No_Import_New_Job` also acts as the workbook "unhide everything" reset and forces `Application.CalculateFull`; A2 flag "Existing" on MCAA RECAP prevents re-prompting.
