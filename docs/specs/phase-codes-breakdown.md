## 1. Sheet: "Phase Codes" (visible, protected)

### 1a. Purpose
Master cost-code dictionary for the whole workbook. Defines 8 cost **divisions** and up to 99 numbered **phase codes** (01–99) in each. A full phase code is the string `"<division>-<NN>"` (e.g. `3-15` = SM Field / Galvanized Duct). Every labor/material line on TakeOff is tagged with one of these codes; Booking Report, MCAA RECAP and the Booking CSV export key off them. Hidden columns O/Q/S hold the pre-composed code strings used as dropdown lists on TakeOff.

### 1b. Visible layout
Matrix: 99 rows x 8 division columns.

- `B1:I1` (merged): banner "Division"
- Row 2: division numbers 1..8 in cols B..I
- Row 3: division names (see table below)
- `A2:A3` (merged): "Phase Codes"
- `A4:A102`: code number 01..99 (rows 4–12 are literal text "01".."09", rows 13–102 numeric 10..99; number format `00`). Row r ⇒ code `NN = r-3`.
- `B4:I102`: description of code NN for that division (blank = unused code slot).
- Columns `K:M` area: 3 macro buttons (see 1f).

Divisions (locked constants, row 2/3):

| Div | Col | Name |
|---|---|---|
| 1 | B | General Conditions |
| 2 | C | SM Shop |
| 3 | D | SM Field |
| 4 | E | Pipe Shop |
| 5 | F | Plumbing Field |
| 6 | G | Pipefitter Field |
| 7 | H | Subcontractor |
| 8 | I | Architectural Field |

Hidden columns: **O, P, R, S** (P and R are empty spacers). O/Q/S carry the composed code lists (Q is NOT hidden but narrow):

- `O3` "Field Phase Codes", `O4:O696` = 693 codes: divisions **1,3,4,5,6,7,8** x 01–99 (text, nf `@`) — named range **Phase_Code_List_Field**
- `Q3` "Shop Phase Codes", `Q4:Q102` = 99 codes: division **2** x 01–99 — named range **Phase_Code_List_Shop**
- `S3` "Material Phase Codes", `S4:S795` = 792 codes: divisions **1–8** x 01–99 — named range **Phase_Code_List_Material**

Verified with Python: all three lists are perfectly regular `D-NN` sequences with no gaps, so the app can generate them from the division sets instead of storing 1,584 strings (data.json includes both the generator spec and the full arrays).

### 1c. USER INPUTS (unlocked cells)
There are **no formulas** on this sheet. The only unlocked cells are *custom description slots*: every description cell in `B4:I102` that does **not** hold a locked standard description is unlocked so estimators can define job-specific codes. In the extracted bid, 19 slots are filled (marked `"custom": true` in data.json):

- Div 2 (C): rows 42–46 → codes 2-39..2-43 ("Fan Deck room", "ED Penthouse", "Small Penthouse", "Temp Air ducting", "Boiler room ducting")
- Div 3 (D): rows 42–53 → codes 3-39..3-50 ("Fan Deck room" … "Faster Permits")
- Div 6 (G): row 43 → 6-40 ("Package 2 work")
- Div 7 (H): row 20 → 7-17 ("Duct Cleaning/Cleanup")

Raw-XML check confirms: all *blank* description cells in the custom region (≈rows 28–102 depending on column) carry unlocked styles. **App rule:** standard descriptions are read-only reference data; any code slot without a standard description is a free-text user input (per-bid).

### 1d. COMPANY CONSTANTS
All locked, literal (no rates on this sheet — it is pure reference data):
- Division numbers/names (B2:I3).
- 270 standard phase-code descriptions across the 8 divisions — **full dump in data.json → `phaseCodes.divisions[].descriptions`** (code → description, `custom` flag for the 19 bid-specific ones). Notable locked outliers: `3-70` BOLI Adjustments (D73), `1-89`/`3-89` Safety Director Offsite/Onsite (B92/D92), `2-99` Spiral Allocation (C102), `3-99` OCIP Deduct (D102), `7-99` MWESB Subcontractor (H102).
- Code lists O/Q/S as above.

These must be editable settings in the app (company may re-label codes).

### 1e. Cross-sheet consumers
- **TakeOff** data-validation dropdowns: col A (`PC_SM_Material`) ⇒ `Phase_Code_List_Material`; col B (`PC_SM_Shop`) ⇒ `Phase_Code_List_Shop`; col C (`PC_SM_Field`) ⇒ `Phase_Code_List_Field` (applied to every group's line rows, e.g. A41:A69, B41:B69, C41:C69 …).
- **Booking Report** description columns: `=IF('Phase Codes'!B4="","",'Phase Codes'!B4)` etc. — each division block on Booking Report walks the matching Phase Codes column rows 4..102 (named ranges `Codes_GC` = B4:B102, `Codes_Subcontractor` = H4:H102).
- **MCAA RECAP** reverse lookups: `A37:A44`/`A127:A129`: `=IF(B37="","","7-"&INDEX('Phase Codes'!$A$4:$H$102,MATCH(B37,Codes_Subcontractor,0),1))`; `A101:A105`: same with `"1-"` and `Codes_GC`. i.e. `code = div + "-" + padded(codeNumberOfDescription)`. JS: `codeFor(desc, div) { const i = divisions[div].descList.indexOf(desc); return i<0 ? "" : div + "-" + String(i+1).padStart(2,"0"); }` (INDEX col 1 = the A-column code number at the matched row).

### 1f. Buttons (vmlDrawing1, anchored over K1:M8)

App equivalent: export the code matrix (divisions 1–7, i.e. cols B..H) as a "Time Sheet" spreadsheet/CSV.
2. **"Go To Takeoff"** → `Goto_SM_Sheets` (navigate to TakeOff).
3. **"Go To MCAA RECAP"** → `Goto_MCAA_RECAP` (navigate).

## 2. Sheet: "Breakdown" (state: veryHidden, protected, no unlocked cells)

### 2a. Purpose
Internal schedule-of-values report: for each of the 32 TakeOff groups (CAE + groups 1–31) it computes prime cost (shop labor $, field labor $, material $), then spreads the "unassociated" remainder of the total bid (markup, GCs, subs, etc.) across groups pro-rata by cost, yielding a per-group sale price. Warns "Do not use for Bid Alternates!". Never unhidden by any macro (`Sheet14.Visible` line is commented out in `Yes_No_Import_New_Job`); it exists to feed **SM Schedule** task descriptions and as a maintenance report.

### 2b. Layout
Three identical section skeletons:
- **Sheet Metal** rows 5–40: header row 7, data rows 8–39 (the 32 SM TakeOff groups), totals row 40. **Only this section is wired up.**
- **Plumbing** rows 43–66: data rows 46–65, totals row 66 — **stub**: A/B/C/D/E 46–65 are empty (no formulas), only the totals/derived cols exist, so everything is 0.
- **Piping** rows 69–92: data rows 72–91, totals row 92 — stub like Plumbing except E72:E91 = `SUM(B:D)` formulas exist.

Columns: A Description | B Shop Cost | C Field Cost | D Material Cost | E Total Cost | F OCIP Deduct | G % of Job | H Assigned Job Costs | I Total Sale Price | J Equip-Rental add | K Supervision add | L Subcontractor add. Header constants: G3 "Project Total", G4 "Unassociated Trade Cost", J6/J44/J70 (merged J:L) "SUBTRACT THESE VALUES FROM TOTAL SALE PRICE TO REMOVE THEM FROM THE SALE PRICE".

### 2c. Group anchor map
Breakdown row `8+i` maps to TakeOff group `order[i]` where `order = [CAE, 1, 2, …, 31]`. Each group has a description cell `TakeOff!D<desc>` (named `Breakdown_SMCAE`/`Breakdown_SM<n>`) and a totals row `<total>` where `H<total>`=field hours (named `Breakdown_SM_Field_*`), `K<total>`=shop hours (`Breakdown_SM_Shop_*`), `M<total>`=material $ (`Breakdown_SM_Material_*`). Full row table in data.json → `breakdownGroups` (verified cell-by-cell against the extract): CAE {desc 9, total 36}, g1 {40,70}, g2 {74,101}, g3 {105,134}, g4 {138,169}, g5 {173,202}, g6 {206,270}, g7 {274,302}, g8 {306,333}, g9 {337,364}, g10 {368,395}, then +31 per group up to g31 {1019,1046}.

(The similarly-named ranges `Breakdown_FieldLaborCost_*` / `Breakdown_ShopLaborCost_*` point at TakeOff cols AG/AH per-line ranges and are consumed by **Price Breakdown**, not by this sheet.)

### 2d. Formula patterns (rows 8–39; i = group index; T = group total row)
```js
// prime costs per group
descr    = TakeOff.D[desc] || ""                        // A: =IF(TakeOff!$D$d="","",TakeOff!$D$d)
shopCost = TakeOff.K[T] * CrewRate_SMShop_Straight      // B:  'Crew Mix'!I86
fieldCost= TakeOff.H[T] * CrewRate_SMField_Straight     // C:  'Crew Mix'!I23
matCost  = TakeOff.M[T]                                 // D
total    = shopCost + fieldCost + matCost               // E: =SUM(B:D)
// OCIP deduction, allocated by share of field-labor cost
ocip     = (OCIP_Req == 1)                              // F ('MCAA RECAP'!C26)
           ? OCIP_Deduct_Total * (fieldCost / (C40 + C66 + C92))   // OCIP!O174
           : 0
// pro-rata spread of everything not captured in prime cost
pct      = total == 0 ? 0 : total / (E40 + E66 + E92)   // G: % of Job
projTotal   = MCAA_RECAP.H70                            // H3 = Info_Total_Bid
unassociated= projTotal - (E40 + E66 + E92)             // H4
assigned = pct * unassociated                           // H: =G8*$H$4
salePrice= total + assigned                             // I: =E8+H8
// informational add-backs (share of specific RECAP buckets)
equipAdd = pct * MCAA_RECAP.J130                        // J: equipment-rental total (SUM J114:J129)
supvAdd  = pct * SUM(MCAA_RECAP.H48:H52)                // K: supervision $ (PM 1-01, 5-01, 6-01, 8-01, 3-01)
subAdd   = pct * MCAA_RECAP.J45                         // L: total subcontract (SUM J36:J44)
```
Totals rows 40/66/92: column sums of their section (`=SUM(x8:x39)` etc.); F has no section total at 66/92 (only F40). Note `SUM($C$40,$C$66,$C$92)` and `$E$40+$E$66+$E$92` include the stub sections, so with SM-only data they equal C40/E40. I40 reproduces the full bid: `I40 == 'MCAA RECAP'!H70` (cached 4,614,770).

Sections 2 (rows 46–65) and 3 (72–91) reuse patterns F,G,H,I,J,K,L against their own row block; their B/C/D inputs are absent (treat as 0).

### 2e. Cross-sheet I/O
Reads: TakeOff (D/H/K/M group cells), `CrewRate_SMShop_Straight` ('Crew Mix'!I86), `CrewRate_SMField_Straight` ('Crew Mix'!I23), `OCIP_Req` ('MCAA RECAP'!C26), `OCIP_Deduct_Total` (OCIP!O174), 'MCAA RECAP'!H70/J130/H48:H52/J45.
Read by: **SM Schedule** `C4,C15,C26,…` (step 11): `=Breakdown!$A9..$A39` — group descriptions become schedule task names. Nothing else reads its dollar columns.

## 3. Sheet: "Booking CSV" (visible, protected, no unlocked cells)

### 3a. Purpose
Staging grid for the accounting-system booking export. VBA `Export.Booking` copies this sheet to a new workbook and saves it as `<TakeOff!A1> Booking Export.csv` (semicolon strings are row-type markers in the target import format). The app should reproduce the CSV byte layout.

### 3b. Grid / record format (rows 1–7, cols A–I; full cell dump incl. cached values in data.json → `bookingCsvTemplate`)
- Row 1 (comment): `A1=";"`, `B1 = Booking_Type==1 ? "Original" : "Change"` (Booking_Type = 'Booking Report'!B16)
- Row 2 (comment): `A2=";"`, `B2 = Certified_Payrole==1 ? "Certified Payrole Yes" : "Certified Payrole No"` ('Booking Report'!C10)
- Row 4 (comment): `A4=";Job Header"`
- Row 5 (job header record): `A5="*"`, `B5=Info_Job_Number` ('Booking Report'!F2), `C5=Info_Job_Name` ('MCAA RECAP'!H6), `D5=Info_Address`, `E5=Info_City`, `F5=Info_State`, `G5=Info_Zip` (all 'Booking Report'!C5/C6/D6/E6), `H5=TODAY()` fmt `mmddyy`
- Row 6 (phase/"P" record): `A6="P"`, `B6="1-01"` (text), `C6='Booking Report'!B22` (phase description), `E6=TODAY()` fmt `mmddyyyy`, `I6=1`
- Row 7 (cost/"C" record): `A7="C"`, `B7="1-01"`, `D7=1`, `E7=TODAY()` fmt `mmddyyyy`, `F7='Booking Report'!D22` (hours, fmt `0.00`), `H7='Booking Report'!E22` (dollars, fmt `0.00`)

### 3c. Quirks
- The template ships wired to **only one phase (1-01, Booking Report row 22)**. A real export would need a P+C record pair per non-empty Booking Report phase row; in the workbook this was evidently handled manually/never generalized. Recommend the app generate P/C pairs for all phases with nonzero hours/dollars.
- `TODAY()` is volatile — export stamps the current date.
- Filename bug: `Export.Booking` builds the name from `TakeOff!A1`, which is **empty**, so the file is literally `" Booking Export.csv"`. App should use job number/name instead.

## 4. Sheet: "Macros" (veryHidden)
Two locked text cells: A1 "Macro's are required to use this workbook.", A3 "Please enable macro's to continue". Pure macro-gate: template save state leaves only this sheet visible (`HideSheet` sets `Sheet12.Visible = xlSheetVisible`, all others veryHidden); `Workbook_Open → YesNoMessageBox` re-shows working sheets and re-hides Macros. **Not needed in the app** (document only).

## 5. Quirks summary
- Phase Codes sheet has zero formulas; everything is literal. Protection password used throughout VBA: `/\rct1c`.
- Phase Codes hidden cols O/P/R/S; P & R empty spacers. Q (Shop list) is a visible narrow column.
- Field list intentionally EXCLUDES division 2 (shop) but INCLUDES division 4 "Pipe Shop"; Material list covers all 8 divisions.
- Breakdown is veryHidden and never unhidden by any macro; SM Schedule silently depends on its A-column.
- Breakdown Plumbing/Piping sections are dead stubs (0s) in this workbook version but their totals participate in the SM section's denominators.
- Breakdown H4 ("Unassociated Trade Cost") has nf `0%` on G4 label cell but H-column is currency; G-column % rounds in display only — keep full precision.
- Booking CSV single-phase limitation + empty-A1 filename bug (above).
- Volatile: `TODAY()` (Booking CSV x3).
- No circular references in these four sheets.
